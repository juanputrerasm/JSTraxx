Cut Textures

Cut Textures from Bitmap.

This panel is used to extract multiple textures from a single Bitmap image, and is activated by copying an image to te clipboard from a grapics program and clicking the Paste Composite button in the Textures Box.

Primarily, this feature is intended to be used for generating a set of textures which describe a road corner, or other composite terrain structure. By creating the composite as a single over-size image, consistency of coloring and alignment of features between adjacent textures is ensured.

In some cases it may be beneficial to make a large image containing several corners (eg a complete circle) and/or ground transitions and then use this facility to extract them all at once.

Defining the grid.

The image display shows the original image (scaled to fit in the box) with an overlayed grid indicating where the textures will be cut. You can extract textures from a selective area of the image by moving the Top Offset and Left Offset around - these define the location (in original-image pixels) where the first texture will be cut. By default they are zero (top left of image).

The number of rows and columns in the grid will be reduced automatically if the Offset values are increased in such a way that the grid would extend beyond the image.

The Rows and Columns counts can be decreased to specify a smaller area of the original image to process.

You can make either 64x64 or 256x256 textures, by selecting the required Texture Size button. The number of allowable rows and columns will of course depend on this setting, since the grid must fit within the original image dimensions.

Note that if the original image is too small (eg you have a 200x200 image and select 256x256) then no textures will be created.

The maximum grid size is 16 rows, 16 columns.

MTM2 Alignment.

For MTM2 tracks, textures should have a small border around them in order to ensure that terrain features line up (eg road markings). Its anyone's guess why they made it that way, but they did... so...

The border needs to be 2 pixels around each edge of each texture, therefore the "active" area of a 64x64 texture is really 60x60 (and 252x252 for 256x256 textures). With the Overlap for MTM2 Alignment option checked, Traxx will space the textures by 60 pixels (or 252) rather than 64 (or 256) with an overlap to provide the border.

No scaling or other processing of the original image is done. Therefore, you need to design the original image on the basis that it will be divided into 60x60 (or 252x252) squares.

For example, if you want to create an image that contains a 3x3 grid of 64x64 textures, the image width should be 3 x 60 + 4 = 184, and NOT 3 x 64 = 192. The formula is:

Image size = (ntextures x 60) + 4  (for 64x64 textures), or

Image size = (ntextures x 252) + 4  (for 256x256 textures).

Note: it is + 4 and not + 2, because there must be a 2-pixel border at both sides of the image.

When you are designing your image, think in units of 60, not 64. In effect, the game scales them back up to 64x64 when you race the track. A pair of textures that makes up the two lanes of a straight road section, for example, should be 120 pixels across in the original image, not 128.

Of course, you can switch this option off, in which case Traxx will create textures with no overlap/border. However, in MTM2, features spanning across textures at an angle will not be aligned correctly in the game (nor, indeed, in the main Traxx display).

Tip: You can use this to convert old textures that are designed to line-up at 64x64 (eg from MTM1 tracks) using the following procedure:

· In your graphics program assemble the oversize image in a 64x64 grid, with everything lined-up (copy the textures out of Traxx into your graphics program). For example, if this is a corner that uses a grid of 3x3 squares the image would be 192x192 (3x64 = 192).

· Resize the image down to a multiple of 60 (you may want to convert to 16-million colors and resample then convert back to 256-colors). In our 3x3 example the new image would be 180x180 (3x60 = 180).

· Add a 2-pixel border around the image (in PSP use "Enlarge Canvas" with "Center image" checked). Our example would now be 184x184 (remember its + 4 because theres 2 extra pixels at both sides).

· Replicate the two pixels around the edges of the image to fill the new blank borders (copy a 2-pixel wide strip from the edge of the valid area).

· Now you can copy and paste this image into Traxx and the new textures should line up correctly in MTM2.

Texture Names.

You must enter a base name in the Texture Base Name box of up to 6 characters. All the textures created will have this name followed by two digits representing the column/row position of the texture in the grid. For example, along the top row - starting at top-left - they will be xxxxxx00.RAW, xxxxxx10.RAW, xxxxxx20.raw etc. Thus, the numbers can be seen as the x/y location of textures within the grid.

Before any textures are created, a check is made that none of the resulting names are already in use, and prompts for a new name if they are.

Tip: When the textures are created, they will be loaded into the Textures Box in grid order, so you may want to paint them into the terrain right away. Then you can save the area as a Pattern, and never have to lay it out again. If you wait til later to load the textures "manually", they may not be listed in order so it wont be as easy to lay them out.

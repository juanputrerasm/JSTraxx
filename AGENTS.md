# Working on JSTraxx

JSTraxx is a web port of Traxx, the Monster Truck Madness 2 track editor. TypeScript, Vite, three.js, OPFS for files, Web Workers for heavy work.

## Rules

- **Traxx is the reference.** `~/dev/Traxx_OnGoing_Updates` (C++, Traxx 1.6.7) is the only source of truth for what the editor does and what it writes. Port from its code, and cite the file and function in a comment.
- **Formats live in OpenPhotex; Traxx's logic lives here.** Parsing and writing files is OpenPhotex's job (`~/dev/OpenPhotex`). What Traxx does with the data stays in JSTraxx: its units, the fields it keeps, the values and number format it writes, its quirks. A Traxx rule never goes into OpenPhotex. A format OpenPhotex cannot read or write yet gets added there, in its own neutral form.
- **OpenPhotex is vendored.** `src/vendor/openphotex` is generated by `npm run vendor` (it builds OpenPhotex and copies it with `--types`). Never edit it. Import modules one by one (`vendor/openphotex/mtm/sit.js`), not `index.js`, so each worker loads only what it uses.
- **`src/core` and `src/worker` never touch the DOM or three.js.** They take and return plain data, so they run in workers and under `node --test`. Only `src/render` imports three.js.
- **Tests.** `npm test` runs `node --test tests/`. Stock-archive checks read a local install (`JSTRAXX_GAMES`, default `~/games`) and skip when it is absent. Game data is never committed.
- **The UI follows Traxx's frame.** Menus, toolbars, shortcuts, prompts and tooltips come from `Traxx/Traxx.rc` and live in `src/ui/shell/commands.ts`. A command with no behaviour yet stays listed and greyed out, so the menus always show the whole of Traxx.
- **Docs and comments** never use em dashes.

## Commands

```sh
npm run dev         # Vite dev server
npm run typecheck
npm test
npm run vendor      # rebuild and re-vendor OpenPhotex after changing it
node scripts/traxx-ui-art.mjs   # regenerate public/ui from Traxx/res
```

# JSTraxx and Traxx: parity checklist

Every feature of Traxx 1.7.3 (`Traxx_OnGoing_Updates` at 4364111; 1.7, 1.7.1, 1.7.2 and 1.7.3 additions are marked), and where it stands in JSTraxx. The
status column is what the code does; the box is for checking it in a browser against Traxx.

Status: **Ported** works as in Traxx. **Changed** works, differently on purpose (the reason
is given). **Added** is not in Traxx. **Not ported** is left out, with the reason.

## Deliberate changes

- Undo covers every mode and keeps many steps.
- Textures mode paints while the button is held.
- Deleting a texture renumbers an animation's first frame too (Traxx leaves it pointing at the wrong texture).
- New objects are appended (Traxx reuses the first empty slot); the list stays dense.
- Model vertices keep full precision (Traxx rounds to whole units for its polygon library).
- Loading art from disk copies it into the browser's ART or MODELS folder, so the track finds it again.
- Purge Unused Models keeps a model a top-crush uses as its base.
- The software renderer is replaced by WebGL; there is no Display Resolution setting (the view fills the window).
- Write POD saves through the browser.
- A pod whose lake tile map is not Traxx's fill (made by another tool, such as a converter) keeps its map: the view, the waterfalls, the checks and Write POD use the pod's own map, and Write POD writes its `.WTR` back unchanged, with no lake errors to refuse. Once a lake, the lake rule or a waterfall changes, the lakes are filled as Traxx fills them; an undo back to the pod's lakes brings the stored map back. Traxx always shows and writes its own fill. The stored map is not saved in the `.TXX` (`StoredLakes`, `src/core/traxx/lakes.ts`).

## Track format version 6 (JSTraxx only)

Traxx 1.7.1 has no version 6; this follows the open specification (openmtm2.github.io/proposals/track-format-v6.md), with the formats in OpenPhotex.

- **Listing and opening.** View POD and Import list `WORLD\<stem>.SI3` tracks as their own entries, beside a `.SIT` or `.SI2` of the same stem. A `.SI3` needs `DATA\<stem>.TXV` with `formatVersion=6`; a bad section 6 key refuses the track with the key named, and a `formatVersion` above 6 is reported and the track still opens. The world is `worldCells` (256 or 512) cells a side. Every grid file (`.CLR`, `.LTE`, `.RA0`-`.RA5`, `.CL0`-`.CL2`) must be N x N or the track is refused. Heights come from `terrainHeightMap` (PNG or 16-bit RAW, N or 4N square, `classic` / `spline` / `fine`), and the `.RAW` the `.LVL` names need not exist; without the key a 256 track follows CP4's rules. Ground boxes may be 8 or 16-bit; the `.WTR` and the `.WFL` are version 1 on a 256-cell world and version 2 on a 512-cell one, any other pairing refused (a refused `.WFL` is said with a warning and the track opens without waterfalls); `.VEG` trees may sit anywhere in the world. Negative positions wrap by the world's side.
- **Heights.** A version 6 track keeps its heights at 1/128 ft in 32-bit integers, so they can go below 0 ft and well above 512 ft. Tools clamp to that range; tracks in CP4's range keep Traxx's 16-bit store and clamps.
- **New track.** File > New > World Size... picks 256 or 512 cells and the terrain grid.
- **Import / Export Heightmap (Version 6).** These are on the Edit menu. Import reads a greyscale PNG or 16-bit RAW of N or 4N square at a step and base the author gives (128 and 0 read a CP4 file as it is), then picks `terrainHeightStep` and `terrainHeightBase` from the imported range (spec section 11). Export writes a 16-bit PNG or RAW at the step and base Write POD would use and names them in the file name.
- **Write POD.** A track is written as `WORLD\<stem>.SI3` with `formatVersion=6` when any of these is true: it has a 512-cell world, heights below 0 ft or at or above 512 ft (or the 32-bit store), or ground boxes that need 16 bits; or it was opened from a `.SI3`. A lake or a waterfall never makes a track version 6. Any other track is written exactly as before. The `.TXV` is Traxx's record, unknown keys and comments kept, with `worldCells`, `terrainHeightMap`, `terrainHeightStep`, `terrainHeightBase` and `terrainGrid` set in place (`terrainHeights` dropped). The step and base are picked from the terrain and ground box range (spec 11). The ones the track was opened or imported with are kept when they still hold every height exactly. Grids are N x N; ground boxes are 8-bit when they fit, else 16-bit; the world's size picks the `.WTR` and `.WFL` version: 1 at 256 cells (any track), 2 at 512 cells. On a 256-cell track a lake or crest outside version 1's 0.5 to 2,048 ft is an error (the lake's "outside 0.5 to 2,048 ft" on a version 6 ground, the fall's crest height), never a version 2 file.
- **Waterfalls.** On a version 6 track the waterfall tool, the checks, the shape preview and the `.WFL` work in the track's world (spec 9.3): crest points anywhere below 16 W in 1/16 ft (W = 32 N ft), crest segments, picks and the menu's nearest crest wrapped the short way at W, the direction check, Orient, SnapToLip, the source pick and the spillway notches on the N x N tile map, and the walk's ground on the N x N (or 4N x 4N) terrain, the 16-bit Classic corners read from the 32-bit 1/128 ft store without Traxx's truncation. A crest height must fit the world's `.WFL`: 1..4096 at 256 cells, `2 * base + 1` .. `2 * (base + 65536 / step)` at 512 cells (the step and base Write POD picks); the Problems list and "Waterfalls need fixing" say which, and the Waterfall window clamps a spring's height to it. Each fall is drawn at its copy nearest the view, a multiple of W away. A track that is not version 6 keeps Traxx's 256 world, 1..4096 and its version 1 reader.
- **Placed objects.** A version 6 document holds up to 16,384 objects (spec 5.3), four times Traxx's `MAXNPODBOXES`. Opening a `.SI3` keeps that many, and insert and paste stop there, saying "Max. 16384 Objects!". Statistics and the open and Write POD messages show the document's limit. Any other track keeps Traxx's 4,096 (`objectLimit`, `src/core/traxx/v6.ts`).
- **`.TXX` (TRAXXV99).** A version 6 track (anything that makes Write POD write a `.SI3`) is saved as `TRAXXV99`, JSTraxx's own generation, not Traxx's; the number is temporary (the final proposal takes Traxx's next free one). Every other track keeps the generation and bytes Traxx 1.8.0 writes (up to V20). Traxx knows `TRAXXV1` to `TRAXXV20` by name and refuses any other header (LoadBinary's FILE_ABORT), so it cannot open a V99 file, and cannot misread one. V99 is Traxx's V20 layout with: every box record ending with V20's `i32` allWx, always (0 for a box that is not a light; V99 files saved before Traxx 1.8.0 was ported lack it and no longer open); `i32 worldCells` before the terrain record; the terrain planes (heights, CLR, light) N x N, run-length coded as before; ground box lower and upper as two `f64`; lake seeds 0..N - 1; the V17 heights as `i32` store bits (16 or 32) then the N x N or 4N x 4N samples at that width; V19's water detail and water mask records always there (an empty extension and length 0 for a map that is not set); and after them the version 6 block (`i32` version 1, `i32` flags: 0x1 opened from a `.SI3`, 0x2 step and base set; `i32 terrainHeightStep`, `i32 terrainHeightBase`). Opening it restores the world size, the 32-bit heights, the step and base and the `.SI3` intent, so Write POD writes the same pod. `src/core/doc/pod-to-txx.ts` (`podToTxx(podBytes, stem)`) converts a POD track to a `.TXX` from node.
- **Limits.**
  - Random Terrain and the Traxx Import / Export Heightmap commands are 256-cell only.
  - The ground box Top / Bottom spins and Adjust Heights' altitude still work in Traxx's 2 ft steps (0..255).
  - Clone TrackEd Track does not list `.SI3` files.
